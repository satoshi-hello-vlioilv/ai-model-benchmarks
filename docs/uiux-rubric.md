# UI/UX 評価基準（100点満点）

評価は画面キャプチャ（`node tests/capture.mjs <dir>`）を実際に見て行う。
主対象は 1728×1152（2160×1440・125%）と 1536×864（FHD・125%）、ライト／ダーク。

## 配点（カテゴリ別の基礎点）

| カテゴリ | 配点 | 観点 |
|---|---|---|
| A. わかりやすさ | 25 | 順序（結論→根拠→詳細）7、チャンク（まとまり・余白による区切り）6、階層（見出し・視覚的な重みの差）7、用語・ラベルの明快さ 5 |
| B. 美しさ | 15 | 余白・整列・リズム 5、タイポグラフィ（サイズ階層・可読性）5、配色（意味・調和・コントラスト）5 |
| C. 統一感 | 12 | 部品の一貫性（カード・表・チャート・タブ）5、色・アイコン・表記の一貫 4、ライト/ダークの一貫 3 |
| D. 使いやすさ | 23 | ステップ数（目的まで何手か）6、考えさせない（現在地・次の行動が分かる）8、直感的（押せる所が分かる・期待どおり動く）5、読みやすい密度 4 |
| E. 信頼性・アクセシビリティ | 10 | 文字の切れ・重なりなし 4、コントラスト 3、色以外の手がかり 3 |
| F. 視覚化 | 15 | 図示率（主要な主張・数値が図で示される）5、図の型の適切さ 4、一目で分かる強調（前注意的特徴）3、文字だけの領域の少なさ 3 |

### F. 視覚化の判定基準
文字を読むより、形・長さ・位置・色で見た方が速く正確に理解できる（前注意処理・二重符号化）。そのため、数値や関係は可能な限り図で示す。

- **図示率**：各画面の主張（首位・差・推移・構成・手順）が、文字だけでなく図（棒・点・線・帯・アイコン・流れ図）でも示されているか。数値が3つ以上並ぶ箇所は図を併用しているか。
- **図の型の適切さ**：比較＝棒・ドット、推移＝線・タイムライン、関係・トレードオフ＝散布図、構成＝積み上げ・帯、順位＝レーン・表内バー、手順＝フロー図、位置づけ＝範囲バー。3D・円グラフの多用・装飾だけの図は減点。
- **一目で分かる強調**：首位・自分の選択・基準線（中央値・人間・現在）が色・太さ・注釈で強調され、凡例を読まなくても主旨が分かるか。
- **文字だけの領域の少なさ**：箇条書き・説明文だけのカードが画面の大半を占めていないか。説明文は図の補足として短く添えられているか。

各観点は 満点 / 3/4 / 1/2 / 1/4 / 0 の5段階で採点する。

## 加点要素（各観点の満点判定に必要）
- 各画面の冒頭で「この画面で分かること」と結論が一目で分かる
- 関連情報がカード・見出しで明確にまとまり、重要度に応じて視覚的な重みが違う
- 押せる要素が一貫した見た目（下線・矢印・ホバー変化・カーソル）で示されている
- 現在地（どの画面・どのタブ・どのフィルター状態か）が常に分かる
- 次の行動（詳しく見る・比べる）への導線がその場にある
- 数値は単位・桁区切り・等幅で揃い、比較しやすい
- ライトとダークで同じ情報が同じ強さで読める
- 表の数値にセル内バー・色の濃淡などの図示が添えられ、表を読まなくても大小が分かる
- 用途・手順・構成などの文章が、アイコン・流れ図・帯に置き換えられている

## 減点要素（見つけるたびに該当観点から減点）
- 文字の切れ・重なり・はみ出し（-1〜-2／箇所）
- 主要な情報が10.5px未満、またはコントラスト不足（-1〜-2）
- カード内に大きな無駄な空白（面積の4割以上）（-1）
- 同じ機能・意味の表記ゆれ、部品の見た目のばらつき（-1）
- ツールチップを見ないと分からない主要情報（-1）
- 押せるか分からない要素、押せそうで押せない要素（-1〜-2）
- 目的に3手以上かかる、または画面の役割が分からない（-2）
- 図で示せる数値・関係が文字・数値の羅列だけで示されている（-1／箇所）
- 文字だけのカードが画面の半分以上を占める（-2）
- 図の型が内容に合わない、装飾だけで情報のない図（-1）
