# ai-model-benchmarks

主要AIモデル（2026-10-24時点・v1.5.0）の性能・価格・速度・仕様を、**1つのHTMLファイル**で比較するダッシュボードです。
`index.html` をブラウザで開くだけで動作します（外部ライブラリ・ネット接続不要）。

## 画面構成（スクロールレス・3階層）

| 階層 | UI | 内容 |
|---|---|---|
| 第1階層 | 左ナビ（キー `1`〜`9`・`0`・`-`・`^`、目的別に区切り） | 概要 / モデル特徴 / 比較 ｜ ベンチマーク / ベンチ解説 ｜ コスト / 速度・容量 / 仕様一覧 ｜ 次世代・動向 / AIニュース / AIの歴史 ｜ データ管理 |
| 第2階層 | 画面上部のタブ | モデル特徴（早見表・プロフィール）、ベンチマークのカテゴリ、ベンチ解説（全体像・個別解説）、次世代・動向（系譜と投入予定・拡散型LM・能力とコスト・基盤と普及・新領域・安全・規制）、AIニュース（最近の話題・情報漏洩と中国AI・ニュース記録）、AIの歴史（年表・性能の伸び）、データ管理（最新化と出典・更新履歴） |
| 第3階層 | ホバー（ツールチップ）／クリック（右ドロワー） | 値の注記・出典・順位、モデル別の全スコアと仕様 |

上部の提供元チップ・「オープンのみ」・「旧世代も表示」は全画面に共通で効きます（ダブルクリックでその提供元のみ表示。絞り込み中は「解除」ボタンが出ます）。
各画面の見出し行には、データから自動生成した**結論の1文**と**次の行動**（例：「上位3を比較 ›」）を表示します。

## 見方（図の共通ルール）

- **ドットレーン**：1本の線上に表示中の全モデルを点で並べ、右ほど大きい値。色付きの番号＝順位（比較画面では選択番号）、灰色＝その他。概要・比較・プロフィール・ベンチ解説で共通です。
- **表内バー**：表の数値の背後の淡い帯で大小を示します（価格・速度・文脈長は対数）。
- 欠損は「—」（未公表・未計測。推測では補完しません）。破線＝中央値や基準（人間の専門家など）。
画面・タブ・フィルター・比較対象はURLハッシュとブラウザに保存され、再訪時に復元されます。

## 解説画面

- **モデル特徴**：早見表（ひとこと要約、カテゴリ別の相対位置のヒートマップ、価格の位置、速度、文脈長）と、プロフィール（全ベンチでの位置レーン、近い選択肢、強み・注意点・向いている用途、データ上の上位指標、カテゴリ別の強さ、価格・速度・文脈・総合指数の立ち位置）。
- **ベンチ解説**：全体像（ベンチ×能力の対応表、飽和度と識別力の散布図、問題数の比較）と、個別解説（何を測るか、評価の流れ図、タスク構成、採点方法、読み方、スコア分布）。
- カテゴリ別の強さは、表示中モデルのうちデータのあるものの**順位**から算出します（100＝首位、0＝最下位）。データがない場合は推測せず「—」とします。

- **次世代・動向**：旧世代（中抜きの点）→ 現行（塗りの点）→ 今後の見通し（期間の帯）を提供元ごとに並べた系譜図と、技術・規制の動向カード（主要な数値・ミニグラフ・「意味すること」・出典）。見通しの確度は帯の塗り方で区別します（塗り＝公式、斜線＝報道、破線＝予測）。
- 旧世代モデルは上部の「旧世代も表示」で全画面に表示できます（系譜図では常に表示）。世代をまたいで比べやすいよう、SWE-bench Pro と Terminal-Bench 2.1 も収録しています。
- 一般提供されていないモデル（審査済み組織のみ）には「限定」の印を付けています。

- **拡散型LM**（次世代・動向のタブ）：自己回帰型との生成手順の違いを図解し、出力速度・応答時間の比較、2015年からの研究とモデルの年表、課題と対策、実用性の見立てをまとめています。拡散型モデルには「拡散」の印を付けています（速度はメーカー公表値）。
- **AIの歴史**：1943年の形式ニューロンから現在までの年表（時代区分・冬の時代つき、2010年より前は圧縮表示）と、学習計算量・パラメータ数・MMLU・文脈長・自律作業時間・価格の推移グラフ。データは `history`（`eras` / `milestones` / `growth`）で差し替えられます。

## データの最新化（HTMLの編集は不要）

「データ管理」画面から次のいずれかで取り込めます。取り込み前にスキーマ検証を行い、エラーがあれば取り込みません。

- **JSONファイルのドロップ／選択**：差分だけを書けば `id` 単位でマージ（全置換も選択可）
- **URLから取得**：CORS許可されたJSONのURLを指定。「起動時に自動で最新化」で毎回最新を取得
- **URLパラメータ**：`index.html?data=https://…/ai-models.json`

「追記用テンプレート」「現在のデータを書き出し」で書式の雛形を取得できます。

### 版の管理と更新履歴

- 版は `MAJOR.MINOR.PATCH`（例：`v1.5.0`）。**MAJOR＝データ形式の非互換な変更／MINOR＝画面・機能の追加／PATCH＝データ更新・修正**。現在の版は `meta.version` で、ヘッダーに表示されます（クリックで更新履歴へ）。
- 更新のたびに `changelog` に1件追加します。公開日時（`"YYYY-MM-DD HH:MM"`・日本時間）・データ基準日・変更内容・その時点の収録件数（`snapshot`）を残し、「データ管理 › 更新履歴」で版ごとの推移と内容を振り返れます。変更内容の `refs` に `m:モデルID`／`n:ニュースID`／`u:見通しID` を書くと、押せる名前になります（モデル詳細には「収録した版」も表示）。

```jsonc
"changelog": [{ "version": "1.5.1", "date": "2026-10-25 10:00", "type": "patch", "asOf": "2026-10-25", "pr": 11,
                "title": "データ更新（10/25）", "summary": "…",
                "snapshot": { "models": 40, "legacy": 12, "bench": 14, "upcoming": 14, "news": 52 },
                "changes": [{ "k": "add", "t": "モデルを追加", "refs": ["m:new-model"] }] }],   // k = feature/add/update/retire/remove/fix/news
```

### ニュースの記録

- `news` に1件ずつ追記します。**発生日（`date`）と、ダッシュボードに記録した日（`recorded`）・版（`ver`）を分けて残す**ため、あとから「いつ何を知ったか」まで振り返れます。
- 確度 `conf` は系譜図と同じ3段階（`official`＝確認済み・`report`＝報道・主張・`forecast`＝未確認）。事実関係を整理する記事は `confirmed`／`alleged`／`disputed` に分けて書きます（推測で断定しない）。
- 情報漏洩・AI悪用の記事は `topic: "leak"` と種類 `type`（`espionage`／`distillation`／`exposure`／`insider`／`policy`）を付けると、「情報漏洩と中国AI」の時系列と一覧に載ります。結論（確かなこと／言い過ぎなこと）と対策は `newsTopics` で更新します。

```jsonc
"news": [{ "id": "n-xxx", "date": "2026-10-25", "cat": "policy", "title": "…", "short": "年表の短い名前", "lead": "結論の1文",
           "conf": "report", "facts": ["…"], "impl": "意味すること", "srcs": ["出典ID"], "recorded": "2026-10-25", "ver": "1.5.1" }]
```

`metric` 指定子：`bench:<id>`（ベンチ値）／`spec:speed`／`spec:context`／`price:blended`（入力3:出力1の混合単価）／`value:<id>`（ベンチ値÷混合単価）。
ベンチマークや提供元を追加すると、各画面（グラフ・ヒートマップ・表・比較）に自動で反映されます。

## データについての注意

- 値は各社発表値と第三者集計（Artificial Analysis、llm-stats、Vellum ほか）を収集したもので、値ごとに出典IDと注記を付けています。
- 推論努力（effort）や実行環境で数値は変わります。条件が異なる値は別系列に分け、**未公表の値は空欄のまま推測で補完していません**。

## 検証（評価関数）

UI/UX の改良手順（採点基準・独立評価・複数案の選定・自動検査）は `CLAUDE.md` と `docs/uiux-rubric.md` にまとめています。


`tests/evaluate.mjs` は、主要解像度（1536×864 = FHD@125%、1728×1152 = 2160×1440@125%、1920×1080、2560×1440）× 全画面 × ライト/ダークで次を自動検査します。

- ページ全体のスクロールが発生しないこと／各パネルの内容が縦横に切れていないこと
- グラフのラベルが領域外へはみ出さず、互いに重ならないこと
- 実行時エラーがないこと、埋め込みデータがスキーマ検証を通ること
- ドロワー・フィルター・データ取り込み（マージ／不正データの拒否）が動作すること

`tests/uxcheck.mjs` は、全画面 × 3セット（1728・1536 のライト、1728 のダーク）で、省略記号による文字の切れ・あふれ・10.5px 未満の文字・コントラスト不足（4.5:1）・ラベルの重なりを検査します（違反0件が合格）。
`tests/capture.mjs` は評価用に全画面とツールチップ・ドロワーの状態を撮影します。

```bash
npm i -D playwright   # 初回のみ
node tests/evaluate.mjs [--shots <スクリーンショット出力先>]
node tests/uxcheck.mjs [--verbose]
node tests/capture.mjs <出力先>
```
